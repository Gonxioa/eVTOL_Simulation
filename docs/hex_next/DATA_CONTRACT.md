# v5观测输入、完整时序与因果诊断契约

## 版本和身份

数据版本`hex_v5_continuous_tasks`；包版本`diagnostic_packet_v1`；模型仍为研究设计`hex_research_v1`。
当前参数及控制器不等同于真实F550或北航PX4。原v4数据、特征和结果保持独立。
新数据包含完整健康段、注入过渡、可用故障段，直到请求结束或仿真包络退出。

## 诊断器可见的观测包

| 字段 | 单位与含义 | 是否进入X |
|---|---|---|
| timestamp | 传感器采样时间s；用于时序检查，不含未来时间 | 否 |
| specific_force_body | FLU机体系观测比力，m/s²；包含已模拟噪声/偏置 | 是，3列 |
| gyro_body | FLU机体系观测角速度，rad/s | 是，3列 |
| attitude_xyzw | 可选观测姿态，Hamilton xyzw，FLU→ENU | 扩展方案取旋转矩阵前两列，6列 |
| motor_command_rad_s | 可选六电机转速命令，rad/s；不是实测RPM | 扩展方案取6列 |
| valid / schema | 数据有效性和版本；无效包清空历史且不推理 | 否 |

电机顺序M0…M5沿用当前研究六旋翼几何，见原`GEOMETRY_AND_CHANNEL_MAP.md`。
传感器安装旋转将原传感器轴比力和陀螺转换到FLU后再构造新包。
直接观测姿态、位置和速度并非EKF；位置、速度不在本轮诊断白名单中。

`imu_only`为6维；`imu_attitude`为12维；`imu_attitude_command`为18维。
新18维与旧`combined`18维内容不同，必须按feature-set及schema分开。
旧`rotation_combined`21维也保留历史身份，不能与新12/18维静默混用。

## 诊断器不可见的字段

任务参考位置/速度/加速度/偏航、任务名称、真实状态、故障效能、注入时刻、标签、
文件名、group/record ID和未来采样不进入X。CSV保留这些字段仅供复现、离线标注与评估。
特征函数只接受`ObservationPacket`，不接受包含真值/参考的整行字典。
离线、CSV回放及仿真诊断回调共用同一特征函数。

## 时钟、窗口和报警

任务提供器只在控制时钟更新一次；控制和导出共用缓存。提高导出频率不改变任务提供器的调用序列。
诊断回调在传感器时钟调用；提高导出频率不会产生重复诊断采样。
当前三者100Hz，动力学最大积分步长2ms。更密的事件可拆分积分，不能要求不同事件网格的浮点状态逐位相同。

当前窗口50点、步进10点；从0.49s的第一完整窗口开始，持续推理到最后可用采样。
不存在故障时刻对齐、故障后专用裁切、全记录归一化或未来插值。
缺样/无效输入清空缓冲，重新积累50点；不复制末值、补全尾部或延长早停记录。
报警设计为`P(fault)>=0.8`连续3窗；持续高概率锁存，解除后允许重触发且冷却1s。
这些是起步设计值，未完成正式验证集选择或概率校准。

飞控反馈延迟作用于控制观测队列；诊断包保留当下传感器采样时间。
报告中的报警延迟是仿真采样时间差，不是已测硬件通信/推理总延迟。

## 标签、分组和去重

离线按注入日程标注纯健康0、跨边界transition=-1、纯注入故障1…18。
纯故障描述注入定义，不证明实际转速/推力已达到稳态。
训练接口只取纯窗口；回放保留过渡窗口的所有预测。

同组19类复用任务、初始状态、风和传感器随机流；故障时刻也按组共享。
随机流分为任务、初始条件、风、传感器、故障时刻，均不依赖类别标签。
旧v4生成种子包含`scenario.label*31`；本轮取消该项，并逐记录检查健康观测前缀相等。
完全相同的同组健康训练窗口仅保留一次，记录每个被去重窗口对应的原窗口ID。
所有完整时序窗口仍保留在连续评估数组，不能以去重删除在线误报或过渡段。

同一配对group及全部19条记录/衍生窗口必须同集合。
本轮所有group均是开发数据，不能后来改称最终未见测试。
归一化仅使用选定训练group中的原始窗口，诊断时加载其固定统计量。

## 完整性和研究边界

生成计划保存完整任务与物理配置、种子、source SHA、CSV/sidecar SHA、记录级与配对group ID。
新任务正常门禁通过才允许造数；变更计划或源码签名时拒绝续跑到旧数据目录。
验证实际转速边界、动态推力=实际Omega²、稳态预测、参考重建、健康前缀及19类覆盖。
早停来源与不足50点的不可评估来源必须留在清单中。
WGAN及正式比较为后续批次；当前v5入口拒绝静默沿用v4故障后指定区间协议。
