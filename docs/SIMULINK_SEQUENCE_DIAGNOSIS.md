# 12维长序列故障识别与事件标注

本入口修正任务定义：**一条完整飞行记录是一个分类样本**。模型连续读取
12路测量，利用此前历史识别飞行中发生的故障，输出整段记录标签和估计的
故障事件区间。1秒独立窗口不再是本入口的训练或主评价单位。

实现状态：代码和合成执行检查可运行；没有宣称已在原始285条仿真记录上重训、
得到新的分类分数或完成独立盲测。配置值是未整定的实现起点。

## 输出语义

| 输出 | 定义 |
|---|---|
| 记录标签 | 健康，或这条长记录中发生的一个电机/严重度故障，共19类 |
| 当前状态 | 截至当前测量的状态概率，供连续事件检测使用 |
| 历史故障概率 | 截至当前时刻，这条记录已经出现的故障类别 |
| 事件区间 | 由模型证据估计的起止时刻，不读取或回填仿真故障真值 |
| 不确定定位 | 已检测故障但类别证据不足时保留Unresolved，不强行标健康 |

例如原始记录0-24秒，3秒注入M1剩余20%效能：整段记录的监督标签为该故障；
辅助当前状态监督在3秒前为健康，3秒后为该故障。3秒是训练/评价真值，绝不传给
推理函数。在线事件可能晚于3秒确认，必须如实报告该延迟。

支持范围与现有数据一致：每条健康或单电机单故障记录。数据类型支持一次故障后
恢复，尚无对应真实仿真验证；不宣称能处理多个不同电机/严重度先后变化或同时故障。
整段离线标签允许依据全部已记录数据；过去时刻的在线预测只允许使用当时及过去数据。

## 结构与完整时间历史

`simulink_sequence_data.py`读取已有原生来源注册表，复用CSV/MAT/参数身份校验
和原12维测量提取链。指令、真实效能、故障编号、故障时刻、参考轨迹、组号均不进入模型。
训练只打开train和validation角色；标准化只拟合train记录，每个实际采样点出现一次。
完整有限但未通过飞行恢复验收的来源保留，避免删除困难工况。

`simulink_sequence_model.py`采用单向LSTM，保留隐状态，并维护因果累计均值/最大值
特征。当前状态头与记录/历史故障头分开，便于区分“现在已健康”和“这条记录曾经故障”。
累计池化使早期特征可以影响末段分类，但并不保证学习到正确故障证据。

训练按完整轨迹前向和反向，打乱记录顺序而不打乱记录内部时间；变长记录用长度掩码
和打包序列处理，padding不参与损失或历史统计。整段标签交叉熵为主损失，另有因果
前缀/当前状态辅助损失，均按每条记录平均。辅助时间点不是独立窗口训练样本。

推理默认每10个新采样点更新一次：100Hz测量下约0.1秒。它是更新周期，不是历史
长度。每次读取连续的新数据并传递全部模型记忆，不重读重叠窗口，也不在真实故障
时刻重置。不同飞行记录之间重置状态。更长实际飞行的泛化仍需实验。

## 数据单位与旧结果

沿用当前V4开发来源时，训练为114条完整记录、验证为57条完整记录；每条通常
2401点×12通道。主评价矩阵总计57个预测，而不是2409个窗口预测。
训练预算改用完整轨迹batch/epoch和实际参数更新次数记录。旧“1秒窗口、前12秒、
4000步”的选择不自动成为新任务的最优配置。新版本默认完整读取24秒来源。

原V4代码、GAN、冻结结果与控制/动力学文件保持历史身份。旧窗口宏F1与新记录级
宏F1属于不同任务，不直接作同口径提升结论。已经曝光的V4测试来源用于历史诊断，
不能重新命名为未见盲测。完成开发后仍需要独立新来源确认。

## 运行

在项目根目录，使用含PyTorch、numpy、pandas、scipy、scikit-learn的Python环境。
默认读取本机已有的：

`output_simulink_gan/v4_evidence_20261105/development_sources.json`

```bash
python run_simulink_sequence.py audit
python run_simulink_sequence.py train
```

每次新实验使用新输出目录；中断后相同来源、配置和代码才可续跑：

```bash
python run_simulink_sequence.py train --resume
```

模型选择按validation整段19类宏F1，再以记录级交叉熵破同分。最佳模型保存为
`output_simulink_sequence/whole_flight_v1_20261106/best.pt`。
事件工作点另行验证，配置中的阈值/持续时间尚未经过实际仿真数据整定。

使用完整验证记录标注：

```bash
python run_simulink_sequence.py annotate --role validation --checkpoint output_simulink_sequence/whole_flight_v1_20261106/best.pt --output output_simulink_sequence/whole_flight_v1_20261106/validation_annotations
```

可用`--registry`指定/重复指定现有签名来源注册表；`--source-root`用于原始项目
迁移后重定位Windows绝对路径的`output_simulink_gan`后缀。
`--device cpu`强制CPU；默认有CUDA时使用CUDA。完整原始来源与权重未存于Git仓库，
需要在原有本机数据所在环境运行正式训练。

```bash
python -m unittest discover -s tests -p test_simulink_sequence.py
python run_simulink_sequence.py demo --device cpu --output output_simulink_sequence/synthetic_smoke
```

demo是19类、三组合成信号的执行检查，训练两轮；全部输出明确标记为合成，不能用来
证明仿真故障识别性能。该入口不生成MATLAB数据，也不训练GAN。

## 产物

| 文件 | 内容 |
|---|---|
| `job.json` | 数据角色、每条来源/测量哈希、配置和代码身份 |
| `history.json` | 每轮整段训练/验证宏F1、准确率、交叉熵与实际更新数 |
| `best.pt`, `last.pt` | 模型、优化器、训练标准化、RNG及续跑状态 |
| `summary.json` | 实际记录数量、选定轮数及完成范围 |
| `record_predictions.csv` | 每条完整飞行记录一行标签与置信度 |
| `*_events.json` | 估计事件边界、检测确认时间、类别修订历史和未决定位 |
| `segment_annotations.csv` | 原始行索引范围对应的健康/故障/未决区间 |
| `*_trace.csv` | 持续读取全过程形成的因果概率轨迹，供核查，不是独立样本 |
| `metrics.json` | 记录级19类宏F1、事件检出/定位覆盖、漏检、延迟与健康误报 |

事件从首次连续证据时刻标注，确认时刻单独记录；原始故障开始时刻只进入训练目标
和事后评价。最终确认的事件类别可回溯标记该事件缓存片段，输出明确属于模型估计。
记录结束时故障仍持续，保存`ongoing_at_record_end`，不伪造修复时间。

检测与定位分别计时；故障前已有报警不会自动计为新故障后成功检出。漏检保留在
覆盖率分母，延迟分位数明确为已检出记录的条件统计。假设每个条件组只有一条完整
健康来源，误报曝光不重复累加各故障记录的健康前缀。独立统计单位仍是条件组。
